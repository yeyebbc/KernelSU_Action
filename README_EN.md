# KernelSU Boot Image Actions

[中文](README.md) | **English**

Builds device-specific **boot.img** releases with [backslashxx/KernelSU](https://github.com/backslashxx/KernelSU); no AnyKernel3 installers.

- Sony Xperia XZ2 Premium H8116 (`aurora`): LineageOS 22 / Android 15, `4.9.337-perf+`.
- Nothing Phone (1) (`Spacewar`): Nothing OS 2.0.5 / Android 13, `5.4.210-qgki-gcfce8884187a`.
- Nothing Phone (1) (`Spacewar`): Nothing OS 3.2 (Spacewar-V3.2-260206-1016), `5.4.289-qgki-g49c0dcb3dc63`.

## Workflows

### Xperia XZ2 Premium H8116

The **Build H8116 Kernel** workflow uses `h8116-lineage/boot.img`, unchanged `h8116-lineage/dtbo.img`, and `config.env`. It builds `Image.gz-dtb` from LineageOS's `tama_aurora_defconfig`, enables the fork's syscall-table hooks, and releases the result as `h8116-<run_number>`.

### Nothing Phone (1)

The **Build Nothing Phone (1) OS 2.0.5** workflow uses `nothing-1-2.0.5/boot.img`, unchanged `nothing-1-2.0.5/dtbo.img`, and `config-nothing-phone-1.env`. It extracts the stock QGKI configuration from the supplied boot image, builds a raw ARM64 `Image` from NothingOSS's published OS 2.0.5 source, and enables KernelSU's ARM64 branch-link and LSM hooks.

### Nothing Phone (1) — Nothing OS 3.2

The **Build Nothing Phone (1) OS 3.2** workflow uses `nothing-1-3.2-260206/boot.img`, unchanged `nothing-1-3.2-260206/dtbo.img`, and `config-nothing-phone-1-os32.env`. It builds a raw ARM64 `Image` from the `sm7325/v/mr` branch pinned to the OS 3.2 `Spacewar-V3.2-260206-1016` merge, using the same stock-config extraction and KernelSU hooks as the OS 2.0.5 workflow.

Each successful Nothing build publishes a release titled **Nothing Phone (1) OS 2.0.5** or **Nothing Phone (1) OS 3.2** containing `boot.img`, `dtbo.img`, `build-info.txt`, `config.env`, and `kernel.config`. Install the matching Manager from [backslashxx/KernelSU releases](https://github.com/backslashxx/KernelSU/releases), not the official KernelSU Manager.

The stock Nothing kernel suffixes `gcfce8884187a` and `g49c0dcb3dc63` are not commits in the published NothingOSS repository. The workflows retain the requested release strings, but `build-info.txt` records the actual public source commits; matching text alone does not establish vendor-module compatibility.

## KernelSU and Manager compatibility

The kernels are built from [backslashxx/KernelSU](https://github.com/backslashxx/KernelSU) release tag **v3.3.0-28**, whose kernel reports UAPI version **4**.

The Manager compares its own UAPI version against the kernel's and shows **"Kernel update required"** whenever the kernel's is lower, regardless of the app version. Install the matching **v3.3.0-28** Manager APK (`KernelSU_v3.3.0-28_32629-release.apk`), or a newer one only after rebuilding the kernel from a KernelSU revision with the same or higher UAPI version.

A kernel built from an older KernelSU revision reports UAPI v3 and will always show that message: the kernel is out of date, not the app. Each workflow asserts the pinned revision's `kernel/include/uapi/supercall.h` reports the expected UAPI version and fails the build otherwise.

## Image handling

`scripts/repack_boot.py` replaces only the kernel payload while preserving the supplied ramdisk, boot-header metadata, AVB properties, and non-kernel payloads. It supports the supplied H8116 header-v1 image and both Nothing header-v3 images, rebuilds their unsigned AVB hash footers, verifies every preserved field and payload, and rejects output that cannot fit the original boot partition.

The standalone `dtbo.img` is copied and verified unchanged; it is not generated by any kernel build. Do not flash it merely because it is included.

This is not OEM signing and does not make a custom image valid under a locked bootloader's trust chain.

## Before booting or flashing

- **An unlocked bootloader is required.** Back up the current boot image and know the device-specific recovery procedure.
- Images are device- and ROM-specific. Matching a kernel release string does not prove compatibility with installed vendor modules.
- Where supported, test temporarily with `fastboot boot boot.img` before persistent flashing. Do not guess the active slot or write both slots.
- Successful CI compilation and image verification do not prove that the phone boots or that KernelSU works on-device.
