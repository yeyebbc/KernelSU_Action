# KernelSU Action — Xperia XZ2 Premium

[中文](README.md) | **English**

Builds a **boot.img** for the Sony Xperia XZ2 Premium **H8116** (`aurora`), running **LineageOS 22 / Android 15**, with kernel release **4.9.337-perf+** and [backslashxx/KernelSU](https://github.com/backslashxx/KernelSU). It does not create an AnyKernel3 installer.

## Run

1. Keep the boot image from your installed ROM at `h8116-lineage/boot.img` and its matching DTBO at `h8116-lineage/dtbo.img`. The checked-in images are the build inputs; no boot image is downloaded from another device.
2. Push this repository, including those images, to your GitHub fork. Open **Actions**, select the H8116 build workflow, then **Run workflow**.
3. A successful run automatically publishes a GitHub **release** tagged `h8116-<run_number>`, containing `boot.img`, unchanged `dtbo.img`, `build-info.txt`, `config.env`, and `kernel.config`. The existing run artifact remains available.
4. Install the matching Manager from [backslashxx/KernelSU releases](https://github.com/backslashxx/KernelSU/releases), not the official KernelSU Manager.

`config.env` selects the Sony kernel source, revision and toolchain. The device configuration is `tama_aurora_defconfig` from [LineageOS's Sony SDM845 kernel](https://github.com/LineageOS/android_kernel_sony_sdm845/tree/lineage-22.2). KernelSU is built into the kernel with the fork's syscall-table hook mode for Linux 4.9; the old official KernelSU manual patches are not used.

The workflow enables and checks `CONFIG_DEBUG_INFO_DWARF4=y`, retaining debug information while avoiding Clang 19's default DWARF 5 directives, which the legacy assembler in the GCC 4.9 prebuilts cannot parse.

## Image handling

`scripts/repack_boot.py` uses AOSP `unpack_bootimg.py` and `mkbootimg.py` to replace only the kernel payload with the compiled `Image.gz-dtb`. It preserves the supplied boot image's recovery ramdisk, command line, OS/patch level, addresses and other non-kernel payloads. Packaging verifies these fields and payloads after rebuilding.

The supplied boot image has header v1, 4096-byte pages, a 64 MiB partition size, and an unsigned AVB hash footer. Packaging regenerates that footer for the new bytes, preserves the AVB build properties, and verifies its digest. It rejects an image that cannot fit in the boot partition. This is **not** OEM signing and does not make a custom image valid under a locked bootloader's trust chain.

The standalone `dtbo.img` is copied unchanged; it is not generated by the kernel build. Do not flash it merely because it is included: an installation already using the supplied DTBO needs no DTBO change.

## Before booting or flashing

- **An unlocked bootloader is required.** Back up the current boot image and know how to restore it through fastboot/recovery. Unlocking can wipe data and affect Sony DRM features.
- These inputs are device- and ROM-specific. Matching `4.9.337-perf+` alone does not prove compatibility with vendor modules or a different LineageOS build. Check the source revision against your ROM before flashing.
- Where supported, test temporarily with `fastboot boot boot.img` before persistent flashing. Do not guess the active slot or write both slots; use your installed ROM's device-specific flashing procedure.
- A successful CI compilation and image verification do not prove that the phone boots or that KernelSU works on-device. Confirm both on the H8116 before relying on the image.
